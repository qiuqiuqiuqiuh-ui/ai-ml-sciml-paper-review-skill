# 专项检查

仅读取与论文类型和核心主张相关的部分；不要将所有检查变成所有论文的必需条件。

## LLM、生成模型与 Agent

- 核对模型/checkpoint/服务版本、访问日期、prompt、system prompt、解码参数、上下文长度、采样次数、工具和外部信息；避免把系统配置差异全归因于算法。
- 检查训练或预训练数据与测试题重合的已知证据、去重和时间切分。未知训练语料只能产生污染风险，不能直接定论已经泄漏。
- 区分 pass@1、pass@k、best-of-n 和单次结果，匹配采样预算；Agent 比较应披露 token、调用次数、工具预算、重试和失败/超时处理。
- 若使用 LLM-as-a-judge，核对裁判模型与版本、评分提示、顺序随机化、位置/长度/自偏好、盲化和人工一致性。不能把裁判评分直接当作客观真实质量。
- 检查是否选择性报告任务、prompt、成功轨迹或可视化；同时考虑失败率、成本、延迟和目标用户/任务下实际效用。

## 数据集与 Benchmark

- 检查抽样来源、覆盖范围、标注流程、标注一致性、重复/近重复、许可与分布偏差中影响使用或结论的因素。
- 核对 train/validation/test 划分单位、标签与答案泄漏、评价代码、缺失值、排除规则与负例构造；说明数据量与独立样本数的区别。
- 检查任务是否测量所声称的能力，是否可被捷径解决，是否存在天花板/地板效应或排行榜反复调参。
- 区分新数据、新任务和新评估协议的贡献，核对泛化或代表性结论是否超出数据来源范围。

## 理论论文与理论附带主张

- 重建定义、量词、概率空间、假设和定理结论；核对有限样本/渐近、期望/高概率、局部/全局、必要/充分条件的区别。
- 对关键证明逐步检查推导、引用定理的适用条件和边界例子；区分已检查证明、仅阅读证明草图、未取得完整证明。
- 为疑似错误给出具体推导断点或可验证反例。未能理解或未能完成证明不等于证明错误；反例必须满足全部假设。
- 判断理论是否解释实际算法，所需常数/样本规模/理想化条件是否具实践意义。理论界较松不自动否定理论贡献。

## 代码证据与复现核查

- 固定论文与代码版本，定位入口、数据划分、模型、损失和评价路径。核对核心公式到实现的映射，不能仅凭 README 宣称实现一致。
- 沿实际数据流检查关键 tensor shape、dtype、device、归一化拟合范围、train/eval 模式、随机性以及梯度是否经过所声称的模块。只检查与当前主张相关的路径。
- 区分静态发现、最小测试、完整训练和独立复现。代码疑点须给出触发条件与影响；未执行的路径标注待验证。代码缺失或运行失败不自动证伪论文。
- 实际运行前检查脚本副作用、下载与资源需求；先做小规模 smoke test。记录 commit、命令、环境、种子、数据与容差，评价时使用独立测试数据，不通过测试集反复选择复现配置。
